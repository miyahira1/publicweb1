How a Change Happens

No IDE, no laptop, no local dev server. The workflow fits entirely in the Claude.ai app on a phone:

1

Open Claude Code on the phone

The Claude.ai app connects to a remote container that already has the repo cloned. Claude Code runs in that container — it can read files, run commands, and edit code.

2

Describe what to build

Type (or speak) what you want: "add audio playback to kunkunshi", "create a notes section". Claude reads the codebase first, then plans and implements the change.

3

Claude edits files and commits

The AI writes the HTML/JS/JSON directly, runs git add & commit with a clear message, then pushes to the feature branch on GitHub.

4

GitHub Pages deploys automatically

Within ~60 seconds, GitHub's CDN picks up the new files. No build step, no CI/CD pipeline to configure — just static files, served instantly.

5

Refresh and verify

Open the live URL on the same phone. If something looks off, describe the fix — Claude patches it and pushes again in minutes.

File Architecture

The whole site is plain files. No bundler, no framework install, no node_modules. React is loaded from a CDN at runtime.

/ ← repo root (GitHub Pages serves from here)
├── index.html ← hub page (React via CDN)
├── .nojekyll ← disables Jekyll (lets _index.json be served)
├── shared/
│ ├── style.css ← design tokens, shared by every page
│ └── tools.js ← ← add 1 object here to add a new card
├── games/snake/
│ └── index.html ← self-contained game
├── tools/kunkunshi/
│ ├── index.html ← React app, songs viewer
│ └── songs/ ← JSON song files
└── notes/how-it-works/
└── index.html ← you are here

Adding a new tool takes two steps: create a directory with an index.html, then add one object to shared/tools.js. The hub card appears automatically.

Advantages

💰
Zero cost
GitHub Pages is free for public repos. No server, no database, no monthly bill — ever.
🚀
Instant deploys
Push to main → live in ~60 seconds. No build pipeline, no Docker, no deployment dashboards to manage.
📱
Truly mobile
Claude Code's remote container means the "dev environment" runs in the cloud. Your phone is just a terminal.
📜
Git history
Every change is versioned. Roll back anything. The commit log is also a design journal.
🌍
Global CDN
GitHub Pages is backed by Fastly. Files are cached at edge nodes worldwide — fast everywhere.
🤖
AI velocity
A feature that would take hours from scratch gets done in one conversation. Claude handles boilerplate, debugging, and commits.

Limitations

🚫
No backend
Static only. No user accounts, no persistent data, no server-side logic. Everything runs in the browser — or it doesn't run at all.
⏳
CDN cache lag
After a push, old versions can linger for 1–5 minutes at edge nodes. Hard-refresh or wait it out.
🔓
Everything is public
Public repo = public source. No secrets or API keys can ever live in the repo. All logic must be client-safe.
🐛
No local preview
Reviewing changes on mobile means pushing to see them live. Broken code goes public briefly — though it's easy to revert.
⚙️
Jekyll quirks
GitHub Pages runs Jekyll by default. Files starting with _ (like _index.json) are silently suppressed unless you add a .nojekyll file.
🔋
Session limits
Claude Code remote sessions time out after inactivity. Long gaps mid-task mean starting a fresh context — though the git history bridges continuity.

The Bigger Point

The goal was never to build the most technically impressive site. It was to see how much a single person — on a phone, in spare moments — can ship when the heavy lifting is handled by an AI.

The answer so far: a lot. A Snake game with Web Audio, a full Okinawan music notation viewer with audio playback, a responsive hub, and this note — all built in a handful of sessions without opening a laptop.

The constraint is no longer "can I write the code?" It's "can I describe what I want clearly enough?" That's a much more interesting constraint to work within.
